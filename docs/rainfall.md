# 降雨序列转换与 MIKE 导入

网页入口：[MikeConverterTools → 降雨序列](https://gaomenggu.github.io/MikeConverterTools/)。
文件在浏览器内处理，输出 CSV 或 Tab TXT，随后在 MIKE 中导入并另存为 DFS0。
网页不直接生成二进制 DFS0，不上传源文件。

## 暴雨公式生成芝加哥雨型

在“序列来源”选择“暴雨公式 · 芝加哥雨型”。公式模板收录下列已知结构，
所有地方系数及芝加哥雨型参数均由用户填写，不预填城市系数。
公式以可编辑分式显示，A、C 位于分子，b 位于分母，n 位于指数位置；
重现期、历时、雨峰系数和步长在公式下方填写。`lg P` 即 `log10(P)`。
切换公式单位时只改变原公式的单位解释，不自动改写已填写的系数。
支持以下公式结构：

```text
含重现期项：i(t,P) = A × (1 + C × log10(P)) / (t + b)^n
已按重现期确定系数：i(t) = Aₚ / (t + b)^n
```

这里 `t` 和 `b` 单位为分钟，`P` 为年；对数为以 10 为底。原公式若在系数外
另乘常数，应在明确量纲后合并到 A。公式输出单位可选 `mm/h`、`mm/min` 或 `L/(s·ha)`，
转换关系为 `1 mm/min = 60 mm/h`、`1 L/(s·ha) = 0.36 mm/h`。
`mm/h`、`mm/min` 显示 i，`L/(s·ha)` 显示 q；符号随单位同步。
第二个模板的 Aₚ 已包含所选重现期影响，
不再重复计算重现期项。其他结构不能硬套模板，也不执行任意输入表达式。

参数要求：A 或 Aₚ > 0，b > 0，0 < n ≤ 1，C ≥ 0，P > 0，0 < r < 1。
填写总历时（分钟）、雨峰系数 r、采样步长（整秒），步长须整除总历时。
可记录公式来源和版本；报告保留完整参数。当前模板不含经核实的地方参数库，
不声称可直接用于五指山或其他城市；地方公式的适用历时、重现期及版本需自行核对。

生成采用连续芝加哥雨型的时段积分，输出**时段平均雨强**。设经单位换算并合并
重现期系数后的强度为 `i(t)=K/(t+b)^n`，则：

```text
H(t) = K × t / (t+b)^n / 60       # IDF 对应雨量，mm
T = 总历时，tp = r × T           # 分钟
S(t) = r × [H(T) - H((tp-t)/r)]                          t ≤ tp
S(t) = r × H(T) + (1-r) × H((t-tp)/(1-r))                t > tp
第 j 时段平均雨强 = [S(tj)-S(tj-1)] × 60 / (tj-tj-1)     # mm/h
```

因此生成总雨量为 `H(T)`，不会因采样步长不同而系统性偏离理论雨量。
起点写 0，从第二条记录起表示前一时段平均值，MIKE 导入必须选
`MeanStepBackward`。图表展示时段平均雨强；采样峰值时刻和数值可能与连续雨型
在 `r×T` 处的瞬时峰值不同，尤其雨峰不在采样边界上时。页面会同时给出雨峰位置、
理论雨量及生成与理论的差值。

生成文件和已有雨强文件共用下述输出格式及 MIKE 导入流程。

## 输入

选择 DAT、TXT 或 CSV，支持 UTF-8、GBK / GB18030。雨强单位可选 `mm/h` 或 `m/s`。
每行一个采样时刻，支持空格、逗号、Tab 或分号分隔；可带“时间 / Time”表头，
其他说明行通过“数据起始行”排除。数据区内坏行、负值、重复或倒序时间立即报错，
不自动跳行、排序或补值。单文件最多 100 MB、200 万条记录。

三种时间格式：

| 模式 | 样例 | 设置 |
| --- | --- | --- |
| 相对时间＋雨强 | `00:01 60` 或 `1 60` | 起始日期时间；数值时间单位为分或秒 |
| 日期时间＋雨强 | `2026-06-26 00:01:00,60` | 保留文件中的日期时间 |
| 单列雨强 | `60` | 起始日期时间＋采样间隔（整秒） |

`HH:mm[:ss]` 始终按经过的时、分、秒解释，支持超过 24 小时的历时。
数值时间从 0 开始；日期格式支持 `YYYY-MM-DD` 或 `YYYY/MM/DD`。
输出统一为当地钟表时间，不进行时区换算，不接受时区后缀或小数秒。

**输入必须是雨强。每时段雨量（mm）和累计雨量（mm）需先按其时间定义处理，
不能直接当作 mm/h。**

## 输出和单位

选择输出 `mm/h` 或 `m/s`：

```text
m/s = mm/h ÷ 3,600,000
mm/h = m/s × 3,600,000
```

CSV 为两列、逗号分隔、无表头：

```text
2026-06-26 00:00:00,0
2026-06-26 00:01:00,60
2026-06-26 00:02:00,0
```

Tab TXT 采用真正的制表符，不使用字面字符 `\t`。输出数值保留 12 位有效数字，
避免将较小的 m/s 雨强按固定小数位错误截为零。

可下载降雨文件、JSON 报告及对应的 MIKE 导入说明。参数变更后必须重新转换。
页面展示雨强过程、记录数、总雨量、峰值及峰值时刻、时间范围和采样间隔。
大序列图表最多抽样约 4,000 点并保留峰值，统计和导出使用完整序列。

## 数据值含义和总雨量

| 输入含义 | MIKE Value type | 总雨量计算 |
| --- | --- | --- |
| 瞬时雨强 | Instantaneous | 相邻时刻的梯形积分 |
| 前一时段平均值，标记在区间后端 | MeanStepBackward | 后端点雨强乘该区间时长 |
| 后一时段平均值，标记在区间前端 | MeanStepForward | 前端点雨强乘该区间时长 |

总雨量仅统计首末记录之间的时间范围；平均值类型尤其要核对端点。
不根据文件扩展名推断物理含义。曲线和总雨量不能代替原始数据定义。
非等间隔数据保留原时刻并提示；不会重采样或强行补零。

举例：0、1、2 分钟的瞬时雨强分别为 0、60、0 mm/h，总雨量为 1 mm。
120 分钟、1 分钟采样且包含起止时刻时，应有 121 条记录。
模型采用 720 个 10 s 时间区间时，需要覆盖 7,200 s；其端点数为 721。
模型步长可以小于降雨采样间隔，二者不必相等。延长雨后排水计算时，应依据
工况准备覆盖完整时间范围的降雨数据，核查降雨结束端点与零雨强时段。

## MIKE Zero / Time Series

1. 新建或导入时间序列，选择 ASCII 文件。
2. CSV 选择 `Delimiter = Comma`；Tab TXT 选择 `Tab`。小数点选择 `Dot`。
3. 日期和时间位于同一列，选择 `Date/time values in one column`。
4. 格式 `YYYY-MM-DD HH:mm:ss`，日期时间第 1 列，数据第 2 列，起始行第 1 行。
5. `Same item type for all variables = Precipitation Rate`，不选 `Item type in row`。
6. 单位选择与输出一致的 `mm/hour` 或 `m/s`。
7. `Value type` 按网页生成的导入说明选择，不一律套用 Instantaneous。
8. 非等间隔序列按非等间隔时间轴导入，核对起止时间、记录数、峰值及雨量后另存 DFS0。
9. 在模型降雨设置中选择对应 DFS0，并核对其时间范围覆盖完整模拟时段。

常见错误：分隔符不匹配会提示缺少 delimiters；数据项类型或单位不匹配可能
无法用于模型降雨。数值 TXT 不含 EUM 类型元数据，导入时仍需明确指定类型和单位。

当前自动验收覆盖浏览器文本输出，最终仍需在所用 MIKE 版本中核对导入结果。
