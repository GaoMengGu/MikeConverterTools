# MikeConverterTools

在浏览器中转换 MIKE 模型输入文件。GitHub Pages 托管静态页面，文件解析、
空间计算与导出均在用户设备的 Web Worker 内进行，不上传文件，不依赖服务器。

在线地址：[gaomenggu.github.io/MikeConverterTools](https://gaomenggu.github.io/MikeConverterTools/)

## 功能

| 功能 | 输入 | 输出 |
| --- | --- | --- |
| 边界转换 | ASCII DXF 闭合 POLYLINE / LWPOLYLINE | MIKE 五列边界 XYZ |
| 地形点转换 | TXT / CSV / XYZ | 三列 XYZ，可过滤低值 |
| 分区赋值 | 点 XYZ、分区 DXF、图层值 TXT | 参数 XYZ，第三列替换为图层对应值 |

支持选择 CGCS2000 三度分带 25～45 带，默认 37 带。可选择边界轮廓，按最大
间距加密直线边界，预览结果并下载 JSON 报告。实际输出包括全部有效点，预览
对大量点进行抽样，不影响输出精度。

## 使用

1. 选择功能和分带。
2. 选择本地输入文件，也可拖放到对应文件框；先用“载入示例”验证流程。
3. 确认文本编码、列顺序和可选过滤/加密参数。
4. 点击“开始转换”，检查输出点数、坐标范围、预览及警告。
5. 下载 XYZ 与报告，在 MIKE 中指定对应投影并核对几何/高程。

输入变更会清除旧结果，避免下载过时数据。运行中可取消，取消通过终止 Worker
中断计算。报告仅下载到本机，不自动保存。

## 坐标能力边界

这不是完整的坐标转换软件，**分带选择仅补带号，不进行重投影或基准转换**。
输入须已采用所选带的投影、不带带号形式的东坐标 X、北坐标 Y，长度与高程为米。

```text
X < 10000000：X_out = X + zone × 1000000
已有相同带号：X 保持不变
已有其他带号：报错停止
Y 保持不变
```

中央经线 = 带号 × 3°E，EPSG = 4488 + 带号。例如 37 带为 111°E / EPSG:4525，
39 带为 117°E / EPSG:4527。仅凭数值不能判断源大地基准；地方坐标、不同中央
经线及北京 54 等数据应先有依据地转换。XYZ 本身不包含完整投影元数据。

## 输入与输出规则

### 边界

只读取模型中的普通多段线，不应用块引用变换或推断嵌套孔洞。CAD 导出建议
为 ASCII R12，独立外轮廓。默认选择闭合线中顶点最多的一条，支持手动选择。
检测开口、自交、重复顶点、零面积、圆弧凸度和非世界平面对象；不自动修补。
圆弧必须先在 CAD 中离散为直线段，加密只是在线性边上插点。

输出不保留原 Z，不能当作三维沟渠 breakline 高程转换器：

```text
X Y 1 0 0
…
firstX firstY 0 0 0
```

### 点文件

支持空格、Tab、逗号或分号。自动识别三列 XYZ、四列点号 XYZ、五列点号 XYZ 描述。
复杂结构应选择自定义列号，从 1 开始；不自动判断 X/Y 是否颠倒。纯表头和其他
无法解析行被跳过并计数，报告列出前 100 条行号，用户须核查有效点有无遗漏。
数值支持科学计数法，拒绝非有限数值。

```text
359000 2091000 700.5
1,359001,2091001,701
```

低值过滤删除 Z 严格小于阈值的点，等于阈值保留。阈值根据当前最终地形决定，
不要用旧原地形最低值误删后来设计的沟底。

### 分区赋值

TXT 中图层名不含空格，不区分大小写；按从上到下顺序优先，重复图层名报错：

```text
ROAD 75
SITE 60
GOU 40
BACKGROUND 12.5
```

数值仅为格式示例，需按实际物理参数确认。重叠时首个匹配图层优先，边界上的点
包含在面内。未覆盖点使用最后一条有效记录的值，保留所有可解析点与原始顺序。
TXT 涉及的目标图层中只要有开口多段线，立即报错，其他图层的开口线不参与。
未找到对应多边形的图层会警告；至少需要一个匹配的有效多边形。

空间索引使用 RBush，边界点包含判定采用稳健算法。仅支持独立简单面，图层
线之间重叠按 TXT 排序；不根据嵌套关系自动创建带孔面。Manning M 和 n 须按
使用处区分，`M=1/n`；本工具不直接生成 DFSU / DFS2，也不运行 MIKE 模拟。

## 大小与编码

- 每个文件最多 100 MB，点文件最多 200 万点；实际可处理规模还受设备内存限制。
- 自动严格尝试 UTF-8，其次 GBK/GB18030；可手动指定。输出为 UTF-8 纯数字文本。
- 预览点最多约 6,000 个；坐标和统计范围依据完整输出。
- 内存中处理整个文件，大文件请先试小样本，必要时拆分。

## Ubuntu / 本地开发

需要 Node.js 24 和 npm。无需 Python、C3D、MIKE 或 .NET。

```bash
git clone https://github.com/GaoMengGu/MikeConverterTools.git
cd MikeConverterTools
npm ci
npm run dev
```

终端显示本地访问地址。可使用 Codex CLI 在该目录开发；先阅读 `AGENTS.md`。
项目不包含实际工程图纸或测点，测试仅用合成数据。

```bash
npm run check
npx playwright install --with-deps chromium
npm run test:browser
npm run build
npm run preview
```

`npm run check` 包含 Vitest 和 TypeScript/生产构建，浏览器测试覆盖桌面、移动、
下载、错误恢复及 Canvas 像素。Node 与浏览器调用同一套核心函数，避免双重实现。

## GitHub Pages

仓库 Settings → Pages → Build and deployment → Source 设置为 **GitHub Actions**。
推送 main 会运行测试、构建、浏览器验收，通过后部署 `dist`。相对资源路径支持
`/MikeConverterTools/` 项目路径，无需服务器路由或 API 密钥。

依赖静态打包，不运行 Python 后端，不利用 GitHub Actions 处理用户上传文件。
GitHub 仓库包含源码和测试，不应提交实际工程数据、下载结果或凭据。

## 目录

```text
src/core/        转换、校验与几何计算
src/worker.ts    文件解码和计算调度
src/main.ts     界面状态和下载
src/preview.ts  真实几何预览
tests/          核心验收
e2e/            浏览器验收
.github/        CI 和部署
docs/           设计及迁移说明
```

原 Windows / Python 工具仍保留在原工作目录，便于回溯。网页端继承已确定的
五列格式、默认 37 带、低值过滤和分区优先级规则；主动拒绝圆弧及自交，避免
旧版“只读顶点直连”产生错误范围。以实际 MIKE 导入与工程几何校核作为最终验收。
